Harness note: libwebp's simple API gives the VP8 decoder ALL bytes up to the end of the buffer (webp_dec.c DecodeInto: io.data_size = headers.data_size - headers.offset), not just the 'VP8 ' chunk payload. So the RIFF pad byte of an odd-sized chunk (and any trailing chunk) is visible to the token reader. e.g. this 19-byte payload (part0=9, 4 partitions -> needs 9 table bytes) is rejected by dixie and by libwebp on the exact payload, but decoded by dwebp when wrapped in RIFF (dwebp_riff). The harness 'dwebp' decoder therefore feeds the raw payload.
