# dixie: the RFC 6386 reference decoder as a differential oracle

`src/` holds the RFC 6386 §20 sources ("dixie"), extracted verbatim from
`../../rfc/rfc6386.txt` by `extract_dixie.py`. The extraction was checked by
compiling it and by comparing non-blank line counts: 6235 code lines in the
RFC's §20 code blocks and 6235 in `src/`. All 24 files of §20.1 to §20.24 are
present. Nobody edits `src/` by hand.

## Build

    ./build.sh

`build.sh` copies `src/` to `gen/`, applies `compat/rfc_errata.sed`, and then
builds three variants of the decoder with clang:

* `dixie_dec`: `-O1 -g`.
* `dixie_dec_asan`: `-fsanitize=address,undefined`. Errors are recoverable, so
  UBSan prints its message and the decode keeps going.
* `dixie_dec_iconv`: `-fsanitize=undefined,implicit-conversion`. Its output is
  informational only.

If `../libwebp-tools/libwebp.a` exists, the script also builds two helper tools:

* `tools/vp8enc`: a libwebp encoder that exposes `config.partitions`, which
  `cwebp` does not.
* `tools/vp8err`: runs libwebp's internal `VP8GetHeaders` and `VP8Decode` on
  exactly the payload, then prints the status and libwebp's error message.

### Shims and compat code (nothing changes dixie's semantics)

| shim | why |
|---|---|
| `compat/vpx_codec.h` | The RFC leaves out libvpx's `vpx/vpx_codec.h`, but `vpx_decoder.h` includes it. The shim provides minimal type declarations: `vpx_codec_err_t` with libvpx's enumerator order, `vpx_codec_ctx_t`, `vpx_codec_iface_t`, `vpx_codec_mmap_t`, the encoder types that `vpx_codec_internal.h` names, and an empty `DEPRECATED` macro used by `vpx_decoder_compat.h`. |
| `compat/vpx_config.h` | Empty. It stands in for libvpx's generated config header, which `mem.h` includes. |
| `compat/vpx/vpx_image.h` | `vpx_image.c` includes `"vpx/vpx_image.h"`, which is libvpx's directory layout. The shim forwards to `gen/vpx_image.h` and also defines `VPX_IMG_FMT_RGB555 = VPX_IMGFMT_RGB555`, because the RFC header misspells that enumerator. |
| `compat/rfc_errata.sed` | Fixes a typo in the RFC text. `tokens.c` declares `short coeffs = tokens->coeffs + ...`, which must be `short *coeffs`: modern clang refuses to compile the original, and older compilers silently truncate the pointer. This is the only change made to the source. |
| `dixie_dec.c` sets `ctx->error.setjmp = 1` | The RFC code calls `setjmp()` in `vp8_dixie_decode_frame` but never sets `error.setjmp`. As a result, `vpx_internal_error()` records the error and *returns*, and decoding carries on with corrupt state. libvpx sets this flag around its own `setjmp`, and the driver does the same. Setting `DIXIE_NO_SETJMP=1` keeps the RFC-literal behaviour (see the sanitizer findings below). |

`malloc.h`/`memalign` (glibc) and the `static` `vpx_internal_error` in
`vpx_codec_internal.h` need no shim. Nothing references `vp8_dixie_iface`, so
it is not needed either.

## Driver

    dixie_dec <input> <output>        # env: DIXIE_DUMP=1 prints parsed headers to stderr

* **Input.** A file that starts with `RIFF????WEBP` is searched for its first
  `'VP8 '` chunk. Top-level chunks start at offset 12, each chunk is padded to
  an even length, and an `ANMF` chunk is searched recursively from its payload
  offset + 16. The decoder gets exactly that chunk's payload, cut off at the end
  of the file. Any other file is treated as a raw VP8 payload.
* **Driver checks before decoding.**
  * `size>=1 && data[0]&1` gives `error: driver not a key frame`.
  * `size>=1 && !(data[0]>>4&1)` gives `error: driver frame not shown`.
  * A RIFF file with no VP8 chunk gives `error: driver no VP8 chunk in RIFF/WEBP container`.
* **Decoding.** The context is fresh: `calloc` + `vp8_dixie_decode_init` +
  `vp8_dixie_decode_frame` + `vp8_dixie_decode_destroy`.
* **Output.** u32 LE w, u32 LE h, then Y (w*h), U and V (each
  ((w+1)/2)*((h+1)/2)), cropped from `ref_frames[CURRENT_FRAME]->img`.
  w and h are `frame_hdr.kf.w/h`. The exit code is 0.
* **Errors.** The driver prints `error: <code>:<VPX_CODEC_name> <detail>` to
  stderr, deletes the output file, and exits with 1.

## Corpora

The corpora are generated by `python3 -I make_corpus.py` (seeded and
deterministic) and `python3 -I make_crafted.py`. Together they take about 65 MB.

* `corpus/valid/` (564 files):
  * `ext/`: 100 symlinks to every lossy file in `corpus-src/libwebp-test-data`
    and `image-webp/tests/images`.
  * `cwebp/`: 300 files made by `cwebp` with random `-q -m -f -sharpness -strong/-nostrong -segments -sns -partition_limit -pass -af -sharp_yuv -pre -crop -resize`.
    The arguments for each file are in its `.args` file.
  * `enc/`: 160 files made by `tools/vp8enc`, with `partitions=0..3`
    (1, 2, 4 or 8 token partitions), segments, filter settings and so on.
  * `bench/`: four 1024x1024 files, `bench_1MP_*.webp`.

  The sources are small: synthetic PPMs in `corpus/sources/` at sizes from 1x1
  and 1x17 up to 256x256, plus real images converted to PPM.
* `corpus/corrupt/` (10241 `.vp8` raw payloads): mutations of 40 small
  sources. The file name is `<source>__<mutation>.vp8`. The mutation classes
  are:
  * `tag`: every bit of the frame tag.
  * `p0size`: the first-partition size set to specific values.
  * `start`: the start code.
  * `dim`: every bit of the width, height and scale fields.
  * `hdr`: bits and bytes in the first 20 bytes of partition 0.
  * `ptab`: the partition-size table, k = 1..7 entries, and the bytes after partition 0.
  * `tok`: the token data.
  * `rflip`/`rbyte`: random bit flips and byte overwrites.
  * `trunc`: truncations.
  * `append`: appended garbage.
* `corpus/crafted/` (80 files; see `NOTES.txt`): made with `tools/vp8craft.py`,
  which parses partition 0 in Python, re-encodes it with modified header
  fields, and keeps the mode bools and token data unchanged. The parse and
  re-encode round trip is bit-exact on the valid corpus. These files target
  the quirks below.

## Harness

    python3 -I compare.py --decoders dixie,dixie_asan,lean_spec,lean_impl,lean_libwebp,dwebp,dwebp_noasm \
        --files corpus/valid [more dirs | files | list.txt] [--jobs 32] [--timeout 20] \
        [--examples 20] [--report reports/name]

Status of each decoder on each file:

* `ok`: exit 0 and an output file.
* `reject`: exit 1. For dwebp, any non-zero exit.
* `crash`: any other exit, or exit 0 without an output file.
* `timeout`.

For every pair of decoders the report counts `both_ok_same`, `both_ok_diff`
(with the differing planes, the number of differing samples, the maximum
difference and the first differing sample), `A_ok_B_reject`, `A_reject_B_ok`,
`both_reject` and `crash_or_timeout`. Examples are grouped by rejection reason
and mutation class. The report also has rejection-reason histograms and a
summary of sanitizer reports by source location. It writes `reports/<name>.txt`
and `.json`.

| decoder | runs |
|---|---|
| `dixie` | `dixie_dec` |
| `dixie_asan` | `dixie_dec_asan` with `ASAN_OPTIONS=exitcode=86`, so an ASan abort counts as a crash and not as exit 1. UBSan prints its reports. |
| `dixie_iconv` | the implicit-conversion build, informational only |
| `dixie_nosetjmp` | the ASan build with `DIXIE_NO_SETJMP=1`, which is the RFC-literal behaviour |
| `dwebp` | `dwebp -nodither -yuv` on exactly the payload. A payload of 12 bytes or more is passed raw; a shorter one is wrapped in a minimal RIFF. |
| `dwebp_noasm` | the same as `dwebp`, plus `-noasm` |
| `dwebp_riff` | `dwebp` on the payload re-wrapped in RIFF. libwebp's VP8 decoder can then see the pad byte. |
| `dwebp_file` | `dwebp` on the original file |
| `libwebp_vp8` | `tools/vp8err`: accept or reject plus libwebp's message. It produces no planes. |
| `lean_spec`, `lean_impl`, `lean_libwebp` | `webp-lean/.lake/build/bin/vp8-check {in} frame {out} spec\|impl\|libwebp` |

## Results

The final reports are `reports/final_{valid,corrupt,crafted}.txt`, plus
`reports/fuzz_repro.txt` and `reports/examples.txt`.

* **valid (564).** dixie, dixie_asan, dwebp, dwebp -noasm, lean_spec,
  lean_impl and lean_libwebp all agree: every file is ok with identical
  planes.
* **corrupt (10241).**
  * dixie: 7944 ok and 2297 rejected. lean_spec and lean_impl are identical to
    dixie on every file.
  * dixie vs dwebp:
    * 4821 identical.
    * 20 decode in both with different pixels.
    * 3103 decoded by dixie and rejected by libwebp.
    * 17 rejected by dixie and decoded by libwebp.
    * 2280 rejected by both.
  * dixie vs dwebp -noasm: 11 decode in both with different pixels. The other
    counts are the same as against dwebp.
  * lean_libwebp == dwebp (SSE2) on every file.
* **crafted (80).** lean_spec == dixie on every file. dixie vs dwebp: 39
  identical, 31 with different pixels, 7 decoded only by dixie, 3 decoded only
  by libwebp.

### Disagreement categories (examples in `examples/<category>/` with a NOTE.txt)

1. `eof_token_partition`: dixie ok, libwebp says "Premature end-of-file"
   (1305 files). dixie's bool decoder shifts in zeros past the end of a
   partition. libwebp sets `eof` when it decodes a bool whose 8-bit window
   extends past the end, and checks it after every macroblock.
2. `eof_partition0`: dixie ok, libwebp says "Premature end-of-partition0"
   (1464), "cannot parse segment header" (108) or "cannot parse filter header"
   (17). This is the same mechanism in the first partition. libwebp checks
   after the segment header, after the filter header and after each row of
   modes.
3. `partition_first_byte_ff`: dixie ok, libwebp BITSTREAM_ERROR (206). A token
   partition that starts with 0xFF fails libwebp's `VP8InitBitReader` check,
   even when nothing reads that partition. When partition 0 starts with 0xFF,
   dixie rejects as well: color_space decodes as 1.
4. `empty_last_partition`: dixie ok, libwebp rejects (3 + crafted). libwebp
   requires the last token partition to be non-empty.
5. `empty_unused_partition_eof` (crafted): every macroblock is skipped and a
   token partition is empty. libwebp still rejects, because an empty partition
   sets `eof` at init.
6. `reserved_bits`: dixie rejects, libwebp ok (17 + 3 crafted + the fuzz
   repro). dixie rejects color_space != 0 and clamping_type != 0; libwebp
   ignores both.
7. `seg_update_data0`: pixel difference (5 + 2 crafted). When segmentation is
   enabled without data on a key frame, dixie (like libvpx) uses delta mode
   with zero values. libwebp defaults to absolute mode with zeros, which means
   q=0 and lf=0.
8. `lf_level_clamp_order`: pixel difference (2 + 4 crafted). dixie clamps the
   segment level to 0..63 before adding the ref and mode deltas; libwebp
   clamps only at the end.
9. `dequant_qidx_minus1` (crafted only). When a segment's q is -1 and
   `delta_update` is 0, dixie never computes the dequant factors, because its
   cache starts at -1. The factors stay 0 and every residual is dropped.
   libwebp clamps q to 0.
10. `idct_int16_intermediate`: pixel difference (4 corrupt, 10 of the 16 fuzz
    pixel repros, and the crafted `bigcoef_*` files). dixie stores the first
    IDCT pass (`idct_add.c` lines 91-95) and the first WHT pass (lines 30-33)
    in `short`. libwebp's C code uses `int`, and its SSE2 code wraps every
    16-bit operation.
11. `libwebp_simd_vs_c`: dwebp != dwebp -noasm on overflowing coefficients.
    11 of the 20 dixie-vs-dwebp pixel differences in the corrupt corpus are
    only this, and in those files dixie == dwebp -noasm.
12. `riff_pad_byte_visible` (harness note). libwebp's simple API hands the VP8
    decoder every byte up to the end of the buffer. That includes the RIFF pad
    byte and any trailing chunks.

Both decoders reject in all of the following cases, so they do not disagree:

* Truncated or oversized partition sizes. libwebp clamps a partition size that
  is too large, but the last partition then ends up empty, so it rejects
  anyway.
* `sz <= part0 + 10`. On a raw payload, libwebp rejects too.
* Width or height of 0.
* The experimental bit or version > 3.
* A bad start code.

### Sanitizer findings

* **With `error.setjmp=1`** (valid + corrupt + crafted): no AddressSanitizer
  report. UBSan reports three locations, all harmless in practice:
  * `tokens.c:283:19`: `t << 31` in the `eob_mask` computation. This is a left
    shift of 1 into the sign bit. It fires on nearly every file.
  * `predict.c:1382:36`: `0x01010101 * img.y[...]` is a signed int overflow
    when the pixel is 128 or more.
  * `dixie.c:511:44`: `data[9] << 24` is a signed shift overflow when byte 9
    (the height and scale field) is 128 or more.
* **RFC-literal (`DIXIE_NO_SETJMP=1`)**: 1941 of the 10241 corrupt files crash.
  * heap-buffer-overflow at `bool_decoder.h:32:21`, `bool_decoder.h:34:22` and
    `bool_decoder.h:82:29`.
  * heap-buffer-overflow at `dixie.c:140:37`, where the partition table is read
    after "Truncated packet".
  * heap-buffer-overflow at `predict.c:1330:58`.
  * SEGV at `bool_decoder.h:32`, `dixie.c:140`, `dixie_loopfilter.c:356:11`
    and `dixie_loopfilter.c:458:11`.

  See `examples/rfc_literal_no_setjmp/`.
* **Implicit-conversion build** (informational):
  * Coefficient store to `short` at `tokens.c:215`. libwebp truncates the same
    way.
  * IDCT first pass at `idct_add.c:91-95` and WHT first pass at
    `idct_add.c:30-33` (category 10).
  * `vpx_image.c:95/97`, `tokens.c:384` and `dixie.c:510`: harmless
    signed/unsigned conversions.

### Fuzz repros (`../../fuzz/repro`, read-only; `reports/fuzz_repro.txt`)

* `lean-vp8-pixels/*.webp` (16 files): dixie, lean_spec and lean_impl are
  identical to each other on all 16. The current lean_libwebp == dwebp (SSE2)
  on all 16, and dwebp != dwebp -noasm on all 16.
  * In 6 files (094806df, 0b9d7945, 241595f2, 280380e3, 690f3686, b4ab62db),
    dixie == dwebp -noasm. Here libwebp's SIMD and C paths disagree with each
    other (category 11).
  * In the other 10, dixie differs from both libwebp paths because of its int16
    IDCT intermediates (category 10, confirmed with `dixie_dec_iconv`).
* `lean-vp8-eof/not_enough_data.webp`: dixie ok; libwebp says "Premature
  end-of-file" (category 1).
* `lean-vp8-eof/bitstream_error.webp`: dixie ok; libwebp says "cannot parse
  segment header" (category 2).
* `lean-vp8-colorspace/3a16f46c...`: dixie and lean_spec reject it as reserved
  bits; libwebp and lean_libwebp decode it (category 6).
